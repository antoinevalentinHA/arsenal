# Météo — tendance thermique : couche de projection statistique

## Contrats

- `contrats/meteo/tendance_temperature.md` v1.1 → v1.2 (révision) : ajout d'une couche de projection statistique ré-échantillonnée (§4.2), intercalée entre les trois sources météo et les couches `statistics` courte/longue existantes. Corrige un faux `indisponible` : la fenêtre courte (`statistics`) pouvait basculer `unknown` alors que la source restait numériquement valide, faute de rapports assez fréquents. Mécanisme retenu : trigger-based template sensor par axe (déclencheurs `state` + `time_pattern` + `homeassistant: start`), recopie stricte de la source, `availability` dérivée de l'exploitabilité numérique instantanée (§3.3), sans mémoire ni TTL ni fallback ; `force_update` explicitement interdit (`INV-TEND-18`). Cadence `time_pattern: /5`, bornée par `T ≤ W_court / 3`. Ajout des invariants `INV-TEND-15` à `INV-TEND-20`. Grammaire de nommage figée en §11 pour les trois entités de projection. §19 ajouté puis clos dans la même révision (nature de l'écart, résorption, ce que la clôture ne couvre pas) ; §18 conservé à titre historique. Dette de validation terrain des seuils `S_in`/`S_out` (§8.2) non traitée par cette révision, reste ouverte et distincte.
- `contrats/meteo/README.md` : entrée `tendance_temperature.md` mise à jour (v1.2, résorption de l'écart runtime décrit en §18/§19).
- `navigation/domaines/meteo.md` : renvoi vers `tendance_temperature.md` mis à jour (v1.2, couche de projection déployée et validée terrain, PR #839).

## Runtime

- Ajout de `12_template_sensors/meteo/tendance/projection.yaml` : trois trigger-based template sensors — `sensor.temperature_min_chambres_projection`, `sensor.temperature_moyenne_maison_projection`, `sensor.temperature_max_chambres_projection`. Recopie stricte des trois sources (`sensor.temperature_min_chambres`, `sensor.temperature_moyenne_maison`, `sensor.temperature_max_chambres`) ; `availability` ancrée sur l'exploitabilité numérique de la source.
- `13_sensor_platforms/statistics/meteo/tendance_temperature.yaml` : les six capteurs `statistics` (15 min / 60 min, trois axes) repointés de la source directe vers leur projection respective — seul le champ `entity_id` modifié, `unique_id`/`name`/`state_characteristic`/`max_age`/`sampling_size` inchangés.
- `recorder.yaml` : ajout des trois entités de projection (Population A obligatoire, contrat §13).
